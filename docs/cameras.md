# Камеры в Vuesp Hub

Локальный просмотр RTSP-камер в браузере. Поток запускается только на время просмотра и останавливается, когда у камеры не остаётся зрителей.

## Как это работает

```text
Браузер
  └─ Socket.IO /ws/stream/ (cameraId + JWT)
       └─ FFmpeg: RTSP → fragmented MP4 (H.264 baseline)
            └─ Socket.IO → MSE SourceBuffer в <video>
```

- Первый зритель запускает FFmpeg для конкретной камеры.
- Последний отключившийся зритель останавливает FFmpeg через 10 секунд простоя. Небольшая задержка нужна, чтобы пережить reload страницы и не переоткрывать RTSP-соединение.
- fMP4 init segment кешируется на сервере и отдаётся новым зрителям, поэтому подключение к уже идущему потоку работает без перезапуска FFmpeg.
- Страница закрывается или уходит в другой раздел — сокеты закрываются, после grace-периода поток останавливается.
- Карточка подключается, когда попадает во viewport, и не грузит сервер, пока пользователь до неё не дошёл.
- Карточка минималистичная: имя, статус и число зрителей. IP-адрес на карточке не показывается — он есть в модалке редактирования.
- На мобильном информация и кнопки видны всегда. На планшете/десктопе они появляются при наведении или по клику (клик переключает состояние).
- Двойной клик по карточке открывает/закрывает полноэкранный режим — то же действие, что и у кнопки fullscreen.
- Перетаскивание за ручку слева сверху меняет порядок карточек; порядок сохраняется на hub.
- На карточке остались только стоп, fullscreen и редактирование. Удаление перенесено в модалку редактирования.
- Редактирование открывается в той же модалке, что и добавление, с заполненным RTSP-адресом и хостом.
- В модалке есть примеры RTSP-ссылок для Hikvision и Dahua.

## Компоненты

| Файл | Роль |
| --- | --- |
| `server/modules/cameras/application/cameraStore.ts` | Хранит камеры в `cameras.json` (`0600`) внутри data directory |
| `server/modules/cameras/sockets/stream.ts` | Управляет FFmpeg-процессами и Socket.IO-комнатами камер |
| `server/modules/cameras/api/cameraRoutes.ts` | CRUD API `/api/v1/cameras` |
| `frontend/pages/video.vue` | Страница камер, добавление и удаление |
| `frontend/components/cameras/CameraCard.vue` | Карточка с видео и статусом |
| `frontend/composables/useCameraStream.ts` | MSE-плеер и Socket.IO-подключение |

## API

Все запросы требуют JWT, как и остальной `/api/v1`.

```text
GET    /api/v1/cameras
GET    /api/v1/cameras/:id   полный RTSP URL для редактирования
POST   /api/v1/cameras       { name?, url, transcode? }
PATCH  /api/v1/cameras/:id   { name?, url?, transcode? }
PUT    /api/v1/cameras/order { ids: string[] }
DELETE /api/v1/cameras/:id
```

`GET` возвращает только `id`, `name`, `host`, `transcode`, `createdAt` и статус потока. Полный RTSP URL с логином и паролем никогда не уходит в браузер.

## FFmpeg

По умолчанию используется бинарник из `ffmpeg-static`. Путь можно переопределить:

```bash
VUESP_FFMPEG_PATH=/usr/bin/ffmpeg npm run hub
```

Для Electron бинарник распаковывается из `app.asar` через `asar.unpack` в `forge.config.js`.

## Режимы

- `transcode: true` — FFmpeg приводит поток к H.264 baseline, 1280×720 max, 15 fps. Работает во всех браузерах.
- `transcode: false` — копирует видеопоток без перекодирования. Подходит только для H.264-камер и экономит CPU.

## Ограничения

- Аудио пока не передаётся (`-an`).
- Один FFmpeg-процесс на камеру, независимо от числа зрителей.
- При ошибке FFmpeg статус камеры становится `error`; пользователь может нажать «Повторить».
- URL камер хранятся в data directory и не попадают в git.
